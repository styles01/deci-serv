## TOP FINDINGS (full detail)

### A. `tools/equivalence.py` + `tools/cases.py` + `tools/equivalence_mlx.py` — a numerical-equivalence gate for any serving-path change

**WHAT.** A fixed 22-question / 7-call case set (`tools/cases.py:90-158`) — all three question types, 2–12 options, English/German/Hindi states, a JSON-object state and a conversation-array state, plus one case pinned to `typed-decisions` — run through (1) the SDK reference (`laya.Agent.system_one`, one forward per request, `tools/equivalence.py:59-70`) and (2) the served engine path in every dtype/mode combination, *batched the way the micro-batcher batches* (all rows in one padded forward, `equivalence.py:80-91`) and once per case. Comparison (`compare()`, `equivalence.py:109-121`): max |Δp| over probabilities as the client sees them (rounded to 4dp → 1e-4 floor) + whether any argmax moved. Ship gate: **max |Δp| < 5e-3 AND 100% argmax agreement** (`equivalence.py:190`, exit code 1 otherwise). `equivalence_mlx.py:94-154` reuses the same reference/gate for a *different implementation* (MLX port) and additionally checks the two routers agree on checkpoint AND reason string (`compare_routing`, `equivalence_mlx.py:76-91`). Checkpoints loaded one at a time and freed so the whole thing needs one model in memory (`equivalence.py:51-56`).

**WHY valuable.** This is the methodology that decided their defaults: `autocast/eager` = 0.00e+00 Δp (batching across callers provably changes nothing); `bf16` params = 2.1e-2 Δp + one flipped argmax on a 0.157-confidence score question → refused despite 15–35% speedup (`docs/serving-options.md:36-56`, `bench/results.md:84-120`). We run a fine-tuned Laya on a DGX Spark behind our own gate with our own batching/adapter path — we currently have **no** regression check that our served answers equal the SDK's. Any change to our adapter, batching, dtype, or the fine-tune itself currently "passes" by not crashing.

**HOW to adopt.** Port `tools/cases.py` nearly verbatim (it doubles as a smoke-test corpus; swap in one DeciServ-specific case set on our 76k-corpus workflows). Write `tools/equivalence_deciserv.py`: reference = `laya.Agent.system_one` on the Spark (or CPU fp32), candidate = our gate at `192.168.2.185:8710` via the same `POST /decide`. Reuse their `probs_of`/`pick_of`/`compare` (60 lines, numpy only). Wire into CI + after every LoRA merge: gate = 5e-3 / 100% argmax, report max|Δp| per checkpoint. **EFFORT: S** (their code is portable almost as-is; the work is pointing the reference at our models dir).

`tools/smoke.py` (87 lines) is the same case set as an end-to-end smoke: `/readyz` probe, playground-serve check, per-case route assertion (`expect_route`), wall-vs-server latency, one-line answer rendering, failure summary (`smoke.py:50-83`). Adopt as `./run.sh smoke` equivalent for our gate. **EFFORT: S.**

### B. The calibration harness — per-question AUROC vs ground truth collected from live play (`showcase/measure.mjs:171-248`)

**WHAT.** While running episodes, `onTick` collects `{answers, truth, state}` (`measure.mjs:117-128`); each tick contributes one sample per question that has both an answer and a truth label. For nouls: confusion table at the 0.5 threshold, mean-when-true/mean-when-false, **AUROC via pair counting with ties=0.5** (`auroc()`, `measure.mjs:241-248`), and — the clever part — a **`baseline_auroc`**: the ranking AUROC of the naive number the question itself was handed, so the README can say "the model's 0.804 vs the heuristic number it was given, 0.898" (`mines/logic.mjs:250-254` `baseline()`, `measure.mjs:219-221`). For scores: top-level AUROC + exact-match + a true×predicted confusion matrix. Pooling rule: games asking the same question about many entities use `meta.calibration_group` (`mines/logic.mjs:18`) so 12 cells/tick become one table instead of 60 tables of 4.

**WHY valuable.** This is exactly the instrument our gate-eval v2 battery lacks: it converts *any* stream of model answers into per-question discrimination metrics with a built-in "was the question even worth asking" control. Two of its outputs directly attack our roadmap items: (1) it's how you'd validate the fine-tuned checkpoint's probabilities against our 3-layer policy's thresholds (their headline finding — "ranking excellent, reading as probability is not": hopper flap AUROC 0.975 over 3,312 ticks but only 561/1,850 reference-flap ticks above 0.5, `showcase/hopper/README.md:61-77` — is the exact argument for measuring OUR thresholds against OUR traffic, which our own policy.py:31 already says "OURS MUST BE REFIT on our traffic"); (2) the honest-negative culture (snake `dead_end` AUROC 0.586 published in `showcase/snake/measurements.json`) is a docs pattern we can mirror.

**HOW to adopt.** (i) Port `gather()`/`calibrate()`/`auroc()` (~80 lines) into `eval/` as a Python module; (ii) give every game/eval harness in `games/` a `truth(state, action)` export (contract: truth is about what the model wanted pre-shield — `harness.mjs:83-85`); (iii) emit a calibration section per game into our game READMEs via the `<!-- measurements -->` marker patcher (`measure.mjs:318-344`). **EFFORT: S** for the metric code, **M** end-to-end with truth functions for our 4+2 games.

### C. Answer to suspect #3 — how the README's 0.975 AUROC was actually computed

**WHAT.** Not a standalone script — it falls out of B. Chain: `showcase/hopper/logic.mjs` defines `heuristic(state)` = "flap whenever the bird is under the gap centre" (`logic.mjs:142-144`); **ground truth for the noul is the reference controller's answer, not physics** — "there is no tick where flapping is strictly required, so 'should flap now' means 'the controller that never dies flaps now'" (`logic.mjs:146-151`, `truth()` returns `{flap: heuristic(state)==="flap"}`). `measure.mjs` then accumulates 3,312 (p, label) pairs across 20 episodes and computes tie-counting AUROC (`measure.mjs:218`), rendering the table into the README between `<!-- measurements -->` markers. No threshold search: the confusion table is at fixed 0.5 (`measure.mjs:204-210`), and the README explicitly interprets the mismatch (mean-when-true 0.49 vs mean-when-false 0.39 → ranking great, calibration at 0.5 poor). The *reference policy itself* is 7 lines (`logic.mjs:142-144`).

**WHY valuable.** It's a cheap, defensible eval pattern for any of our binary gate decisions: define truth as "what our trusted reference/heuristic policy does", sweep episodes, report AUROC + confusion at the operating threshold, and publish the baseline-control AUROC next to it. Directly applicable to our `deciserv/policy.py` model layer (does our fine-tune's risk signals rank deny-class commands above allow-class? their tool_call_guard reported AUC per signal, `docs/use-cases.md:303-308`).

**HOW.** Covered by B's port; add a "reference-policy AUROC" table to our gate-eval harness report. **EFFORT: S** once B exists.

### F. Per-game question-design conventions (suspect #4) — the measured rules are the gold

**WHAT.** Read all six `logic.mjs` + metadata. Shared contract per game: `meta{tick_ms,max_steps,shield,calibration_group?}`, `init/encode/questions/decide/shield/step/random/heuristic/truth/summary`, seeded PRNG with **two independent streams** — `state.rnd` (world) vs `state.prnd` (baseline policies) — so every policy sees the same world for the same seed and baselines never perturb it (`showcase/_lib/prng.mjs:1-13`). Convention highlights, each *measured*, not guessed:

- **Probability→action mapping is plain argmax over choice probabilities with strict `>`** (first option wins ties): paddle `decide` `paddle/logic.mjs:81-94`, snake `snake/logic.mjs:226-247`, crossing `crossing/logic.mjs:135-156`, dungeon `dungeon/logic.mjs:175-207`. The single noul game (hopper) uses a fixed threshold: `p >= 0.5 ? flap : glide` (`hopper/logic.mjs:90-96`). Mines uses argmax over up-to-12 nouls ("open the cell with the highest safe", `mines/logic.mjs:173-183`). **No hysteresis anywhere.** No thresholds on choice probabilities; uncertainty handling is delegated to the code-owned shield, not the decision.
- **Shield interactions**: shields are pure code, counted, and reported per-episode (`harness.mjs:77-80`). Crucial pattern: when the shield overrules, it takes **the model's next-best choice by probability**, not its own preference — snake `shield()` re-ranks safe moves by the model's probabilities and falls back to a code preference only if the model gave none (`snake/logic.mjs:249-266`); same in crossing `:163-175` and dungeon `:216-229`. Hopper/mines deliberately have **no shield** — "the honest read on the answer" (`hopper/logic.mjs:98-101`).
- **Criteria carry the state; the state stays tiny.** Snake's encode is deliberately ~100 tokens because "everything about the individual moves lives in the criteria, and a state that repeats it only costs tokens: 460 tokens per tick measured 73 ms, 100 tokens measure 35" (`snake/logic.mjs:163-180`). Paddle's encode is ONE sentence; all per-option facts live in criteria (`paddle/logic.mjs:48-56`).
- **Measured phrasing lessons (verbatim numbers in comments):** paddle "columns" even at 1 column — "with '1 column' the model stops closing the last step and score falls from 12 to under 1" (`paddle/logic.mjs:63-66`); snake criteria written "in the same words the criteria use" is "the whole trick" (`snake/logic.mjs:182`); crossing's long criteria "made the model pick a cell its own criteria called deadly in 7 of 16 sampled positions" (`crossing/logic.mjs:105-107`); mines percentage-phrasing beats clue-spelling "AUROC 0.79 against 0.46, and a third fewer tokens" (`mines/logic.mjs:160-166`); hopper's 3-fact state beats a 6-fact state 0.96 vs 0.64 AUROC (`hopper/logic.mjs:66-68`); dungeon skips the choice question entirely when `legal()` has one option ("a choice needs two options"; `decide` takes the forced action, `dungeon/logic.mjs:155-164, 178-188`); verdict-first criteria ("deadly: …", "safe: …", `crossing/logic.mjs:108-116`); snake free-space always phrased *relative to snake length* ("a trap: only N free cells, less than the snake is long", `snake/logic.mjs:192-195`).
- **Ground-truth exports per game** feed the calibration harness: exact truth for mines (`truth()` = is-the-cell-safe, `mines/logic.mjs:257-261`), reference-controller truth for hopper, chosen-cell truth for crossing (`truth(state, action)`, `crossing/logic.mjs:232-237`), snake nouls' truth (`snake/logic.mjs:323-326`).

**WHY/HOW.** These are directly liftable into our `games/arcadia_extra.py` / `laya_arcadia.py` ports and any new gate-facing eval scenario: (1) write criteria with verdict-first, count-relative phrasing; (2) keep `encode()` minimal, push per-option facts into criteria; (3) argmax for choices, 0.5 for the single safety noul, and put hysteresis/shielding in code where it's countable; (4) add `truth()`/`baseline()` exports so our ported calibration harness (B) scores every game automatically. Also adopt `meta.calibration_group` for any ask-the-same-question-about-many-things scenario. **EFFORT: S** to adopt as conventions; **M** to retrofit truth() into existing games.
